Our philosophy, in a software sample.

erp Lite

Purpose

There is tremendous functionality in business software systems. Most try to make a version with every known requirement a client could request. Then trim it down for a prospective client when they are interested.

To serve and support all the potential, it requries a massive framework. routes, functions, so much extra code that will not be used, and not needed for most businesses. They give you a list of availabile modules and functions contained in the busiens represnted by those modules. The client only needs to point them out.

I see constraint in that approach. Providing a set defines a boundry. It is your system, it should do what you need it to, what you want it to. Tecnological advanement, modernization, does not have to be restrictive. We dont take shortcuts. Lets make it freeing.

This sample is not fully functional. It is scaffolded. Foundation laid. the SD module coded and assembled.

The objective was to build a tool to povide infrastucure for busines processes, and adhere to lean principles itself. No waste. No overengineering. Simple in its production version. Realiable. More than adequate to create and maintain a custoemr datanase. Create Sales Orders, help manage and plan production. Connect the departments with an intuitive, minimmal learning curve to promote adoption. Address many of the complaints users post today regarding interfaces, and complexity that does not match the ability of the scaled down software.
